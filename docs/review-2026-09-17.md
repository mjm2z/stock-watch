# Stock Watch effectiveness review — September 17, 2026

## Immediate changes prepared

- Hide the disconnected Anthropic analysis section and disable its API by
  default. Re-enabling requires an explicit flag plus both of the legacy
  integration's credentials. Quotes, charts and deterministic scoring remain.
- Bound scan memory: choose the latest eligible SEC document in SQL, fetch its
  JSON only while processing that company, and retain document IDs/hashes.
  Previously the loader fetched every eligible historical payload before
  discarding older versions. The current recovery process reached roughly
  3 GiB on a 3.7 GiB host, with swapping and slow dashboard responses.
  A regression fixture with twelve irrelevant 1 MB documents confirms peak
  traced allocations stay below 4 MB for that small scan.

These changes are tested locally and staged for administrator installation.
They do not change scoring thresholds, weights, order sizes or holding periods.

## Correctness fixes to prioritize next

### 1. Prevent future test prices from selecting a threshold — highest priority

`worker/src/stock_watch_worker/backtest_runner.py:_select_thresholds` selects
candidates by their signal dates inside the validation window, then simulates
them using the entire dataset. Their holding periods can extend into the test
window. Those future outcomes influence the selected threshold.

Reproduced using the existing calibration fixture: the first threshold was 88.
Changing only AAPL prices on/after January 13, the first test date, changed that
threshold to 75. All training/validation-period prices and signals stayed fixed.

Resolution: only use labels fully observed before the selection cutoff. Purge
validation trades whose exits cross the cutoff, preserve adequate history for
features, and enforce a test proving future-price changes cannot affect prior
selection. Record the cutoff, eligible-label count and excluded-label count.
Version corrected results; do not silently relabel previous experiments.

### 2. Do not finalize a holding-period result before the session closes

`forward_outcomes.py:_load_daily_bars` admits the current date without checking
the exchange's closing time or whether the bar is complete. Maintenance runs
at 10:15 AM as well as 5:15 PM Eastern; opening collection stores partial daily
bars. Once written, outcomes use conflict-ignore persistence and are not updated.

Reproduced in an isolated fixture: the five-session outcome ending August 24
was finalized at 10 AM Eastern on August 24. This demonstrates the missing gate;
it does not establish that a production outcome has already been affected.

Resolution: require completed exchange sessions, including early closes, plus
fresh end-of-session ingestion. Show awaiting close, awaiting data, ready and
evaluated separately. Audit existing outcomes against their recorded entry,
exit and observation timestamps before deciding whether recomputation is needed.

### 3. Make scan decisions understandable from the dashboard

The worker already persists factor contributions, reasons, source references,
order intents and audit events. The UI exposes only part of that evidence.
The signal table does not display its available `asOf` field and calls the
latest cached adjusted daily close a price without showing that observation's
time. Rejected signals with no outcome are displayed as Pending, although the
outcome evaluator currently only evaluates qualified signals.

Add a linked decision history:

**Scan → Data checks → Score → Eligibility → Order → Fill → Exit → Evaluation**

Each step should show its timestamp, status, reason, relevant inputs, source
age and links to its scan/signal/order IDs and strategy version. Add a scan
summary showing unique companies, scored horizons, rejection reasons, eligible
orders, submitted orders, fills and provider failures. A stock can qualify yet
receive no order because of an existing lot or a ticker limit; show that reason.
Add ticker, strategy, date, scan, reason and error filters with pagination and
export. Reuse Home Ops for machine/service health; keep trading explanations here.

### 4. Improve data-quality meaning before adjusting scores

- The collector uses IEX bars. Liquidity thresholds of $20M/$50M/$100M currently
  apply to that feed's dollar volume. IEX covers one exchange, not total-market
  volume. Measure which rejections come from this mismatch, then use an
  appropriate consolidated source or an explicitly validated feed-specific rule.
  Do not lower thresholds simply to force trades.
- Completeness is the weight of available pillars. A pillar with one of several
  inputs can count as fully available. Show underlying field coverage, age and
  missing reasons separately; veto stale or critically incomplete inputs.
- News uses a small deterministic word lexicon and has 15% weight. No matched
  articles can produce a neutral score when coverage is marked complete.
  Distinguish no relevant news, neutral news, missing coverage and stale news.
  Evaluate the news contribution with/without it on honest held-out data.

Provider reference: [Alpaca market-data FAQ](https://docs.alpaca.markets/us/docs/market-data-faq).

### 5. Separate ranking, research performance and execution performance

The same score is copied into 5/21/63/105-session signals. Those are four
evaluation horizons for one ranking, not four independently learned forecasts.
Use “ranking score,” not confidence/probability. Show company counts separately
from horizon observations and evaluate each horizon independently.

Research outcomes deliberately use next-session entry; paper execution uses
actual broker fills. Show both and explain their different timing. Backtest
portfolio results use unlimited external funding for fixed-size lots, which is
already labeled. Add a fixed-capital comparison, cash constraints, execution
delay and cost sensitivity if assessing deployable strategy performance.

Wilson intervals and underpowered labels already exist, but repeated stocks,
overlapping holding periods and shared market days create dependence. Report
unique securities and dates; use time-block/cohort-aware uncertainty estimates
before interpreting large row counts as strong evidence. Track all attempted
experiments and keep a final untouched evaluation period.

### 6. Remove confusing legacy flows and strengthen research records

`QuickActions` opens `CreateTradeModal`, which writes to the Jotai/localStorage
trade list. The automated Paper view reads the worker database and Alpaca.
These are separate ledgers. Hide or explicitly relabel the browser-local tool,
then migrate any wanted records with provenance; do not silently merge them
into broker history. Watchlists and notes should be server-persisted for LAN use.

The Research page is currently a search box. Build a company page containing
current data with freshness, factor history, news/filing links, recent decisions,
paper positions and outcomes. Add a dated research journal with hypothesis,
evidence, contrary evidence, horizon, review date and eventual assessment.

SEC documents should also be content-deduplicated: identical documents fetched
on different days currently create another large JSON row. Preserve capture
timestamps as small reference records and retain pinned research inputs. Do
not prune historical evidence or original backups as part of a UI cleanup.
